# 本轮细抽（说明 + 总布置 + 横断/墩柱/基础/垫石，分批）

只根据当前图片。输出 **一个 JSON 对象**，不要 Markdown。

## 账本字段（现有键，看不清则 null）

- `girderType`：按 **本图图名/横断/说明** 写结构用词（空心板、小箱梁、T 梁、箱梁等）。看见「预应力」不要默认 T 梁；横断是空心板就写空心板。
- `layoutType`：简支 / 连续 / 桥面连续。先简支后连续且图上写连续，填 **连续**。
- `material`：只填 **主梁** 砼标号。墩台/盖梁/桩另一标号进 extracts（`pierMaterial`），禁止把下部 C25 填进主梁 `material`。
- `code`：工程桩号/桥名，与账本核对规则见提示词头部。
- `region`：省或地区，图签有则填。
- `units`：一联一个对象。跨径与墩柱分开。柱数、柱高读法见 `piers.md`（总布置尺寸、表格、构造图、标高差均可；**不是**只能做盖梁底减承台顶）：

```json
{
  "seq": 1,
  "spansM": [30, 30, 30, 30, 30],
  "supports": [
    {
      "seq": 0,
      "code": "0#",
      "kind": "abutment",
      "columns": [
        {"seq": 1, "side": "left", "heightM": 5.2},
        {"seq": 2, "side": "right", "heightM": 5.4}
      ]
    }
  ]
}
```

图名或说明「n×Lm」（如 7×16m）展开成 n 个 L；以总布置立面分跨标注核对。零散「跨 25m」若与图名孔跨不符，先核对是斜长、桥宽还是邻桥，不要覆盖图名组合。多孔一联不要拆成多联，除非图上明确分联。
`supports`：沿联向从 0 起，n 跨通常 n+1 个墩台。`kind` 仅 `pier` / `abutment`。
**同一墩号上每根柱单独一条 column**。知道几根就写几条，高度读不出也留下行（见 `piers.md`）。
墩柱高只写在 `units[].supports`，不要再把同一数字用 `pierColumnHeightM` 进参数袋。

## extracts（本轮能看见就填）

对象数组。`key` 尽量用目录中的英文键；`label` 用专业中文；`value` 为数字或短字符串；`unit` 如 m、m²、kN/m；`page` 为 PDF 页码（与提示里的当前页一致）；看不清不要编造。

本轮优先（出现在说明、总体布置或本轮所带数量表上就抽；专页尺寸见 `catalog.md`，本页能看见的目录 key 都抽，不要只抽梁高）：

梁高、片梁中心距、一片梁宽、桥面净宽/全宽、护栏宽、铺装厚度、**桥面板厚**；能算则估算本幅 `sdlKNPerM`（厚度×宽度×一般重度，note 写 estimated）。
斜交角、平曲线半径、伸缩缝宽/梁端间隙、分联桩号。
护栏每延米重优先用施工统计/数量表的护栏材料用量反算，**必须看清表是单幅还是左右幅合计**（合计则除以 2 再给本幅）；无截面也不要用「标准防撞墙」硬凑。`note` 写明单幅或双幅。无铺装无护栏则二期留空，不要编标准值。
墩型、每墩柱数、各柱高（总布置标注或表格即可，见 `piers.md`）、基础类型、桩径（常与墩径不同，分 key）。支座类型须是 GJZ/GJZF/盆式等，禁止把 GQF-MZL 当支座；**禁止**用梁距×桥宽反推支座个数。土层按墩号或钻孔抽，缺层留空。图上写明「与××墩相同」才可在 note 写来源；**不要把邻墩土层默默填到本墩**。

不要：钢筋编号表、钢束、钢筋工程数量。铺装/护栏材料用量可以抽。

## 冲突

说明或图名写 n×Lm（如 7×16m）、立面分跨应与之相同。立面上某个「25」若与图名单孔跨不符，先核对是桥宽、斜长还是邻桥，不要改写组合。仍不确定则 `units` 为空，不要平均。
